学 LLM 推理绕不开的第一个名词就是 KV Cache。我原来以为它是个高级优化，弄明白之后发现：**它不是优化，是自回归结构逼出来的必需品**。这篇笔记把我的理解过程记下来。

## 从自回归说起

LLM 生成文本是一个词一个词来的：每出一个新 token，都要对前面**所有** token 做一次 attention。朴素实现下，生成第 N 个 token 时，要把前 N-1 个 token 重新过一遍 Transformer，算出它们的 Key 和 Value。

算一下代价：生成一个 1000 token 的回答，全部重复计算加起来是 O(N²) 级别的矩阵乘。关键在于——**上一步算过的 K 和 V，这一步原封不动还能用**，因为每个 token 的 K、V 只取决于它自己和权重，跟后面生成了什么无关。

KV Cache 就是把这些算过的 K、V 存起来，每步只算新 token 的那一列。用显存换计算。

## 一个让我愣住的事实：推理是显存带宽问题

我一直以为推理速度瓶颈在算力（FLOPS），直到看到 decode 阶段的分析：

- decode 时 batch 里每个序列每步只处理 1 个 token，矩阵乘的形状是"大权重 × 细向量"；
- 这种形状下乘法算不了多少，但**每一步都要把全部权重和 KV Cache 从显存搬进计算单元**；
- 所以瓶颈是显存带宽（GB/s），不是算力（TFLOPS）。

这解释了一堆现象：为什么 batch 越大吞吐越高（一次搬运摊给更多请求）；为什么小 batch 下顶级卡和普通卡差距不大（都在等搬运）；为什么 KV Cache 越长越慢（要搬的东西变多了）。

## KV Cache 到底吃多少显存

每个 token 的 KV Cache 大小（FP16）：

```text
2 × n_layers × n_kv_heads × head_dim × 2 字节
```

`2` 是 K 和 V 各一份，结尾的 `2 字节` 是 FP16。代入一个 70B 级别的模型（80 层、64 个 KV 头、头维 128）：

```text
2 × 80 × 64 × 128 × 2 = 2.6 MB / token
```

一个 32k 上下文的请求就是 **~84 GB**——比模型权重还大。这就是为什么长上下文这么贵，也是 PagedAttention 这类工作出现的直接原因。

## PagedAttention：操作系统课没白上

vLLM 的核心思想一句话就能说完：KV Cache 的显存管理，从"按最大长度预留"改成**操作系统的分页**。

传统方式像 C 语言 malloc：给每个请求按 max_len 预留一整块，请求说了 32k 就留 32k，实际用了 3k，剩下 29k 全浪费（内部碎片能到 60-80%）。PagedAttention 把 KV Cache 切成固定大小的块（block），逻辑连续、物理分散，用一张块表映射——和虚拟内存一模一样。碎片率从百分之几十降到 4% 以内。

我自己的记忆钩子：**vLLM = 给 LLM 推理装了个操作系统**。
