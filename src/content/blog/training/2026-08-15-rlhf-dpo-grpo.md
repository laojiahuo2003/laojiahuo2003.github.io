推理线写完了，开训练线。这篇讲对齐训练三代方法的演化——RLHF、DPO、GRPO。看完最大的体会：**这条线的演化方向是"拆部件"**——每一代都把上一代最贵、最不稳的部件干掉一个。

## 第一代 RLHF：三段式流水线

InstructGPT 确立的经典流程：

```text
SFT（监督微调）        先教模型"会说话"
   ↓
RM（奖励模型训练）     人类对两个回答排序 → 学一个打分器
   ↓
PPO（强化学习微调）    用打分器当裁判，RL 让模型追高分
```

直觉上很顺：人类写不出好答案，但**挑得出哪个好**——把"判断力"蒸馏成 RM，再用 RM 大规模训练。

但流水线贵得有名：**同时要四个模型在显存里**（policy、reference、reward、value），PPO 又是出了名的不稳定（奖励 hacking、模式崩塌）。RM 本身还会被钻空子——模型学会写"看起来会讨 RM 喜欢"的话（比如更长的、排比更多的），而非真的更好。

## 第二代 DPO：奖励模型，拆了

DPO 的主张：**RM 和 RL 两个部件，一个数学变换就能全拆掉。**

核心推导的直觉版：最优 policy 和 reward 之间有个闭式关系，把它反过来——**人类偏好数据可以直接推出 policy 的更新方向**，不需要先学打分器再 RL。

```text
RLHF：偏好 → 训 RM → RL 逼近   （两步，各有各的不稳）
DPO ：偏好 → 直接更新 policy   （一步，监督学习的感觉）
```

训练体验从"驯野兽"变成"普通的损失函数"——稳定、省显存（不用四个模型）、实现简单。代价是离线（吃固定的偏好数据集，没有在线探索），上限据说略低于精心调的 PPO——但工程界的选票很诚实：DPO 及其变体成了开源社区的事实标配。

## 第三代 GRPO：价值网络，也拆了

DeepSeekMath 带火、DeepSeek-R1 发扬光大的方案，用在**可验证任务**（数学、代码能自动判对错）上：

PPO 的另一个大部件是 value network（估计"当前状态值多少钱"来降低方差）——又一个要训练的大模型。GRPO 的拆法：**一组同类比的答案内部互相比较**：

```text
对同一个问题采样 G 个回答
组内平均分 = baseline
每个回答的 advantage = 自己的奖励 − 组内平均
```

比组内平均好的被强化、差的被抑制。不需要额外训 value 网络，baseline 白拿——**用"同伴成绩"当锚点，替代"预测的成绩"**。

这个设计便宜、稳定，而且和 RLVR（可验证奖励）是绝配：判分不要人（单元测试、答案比对），baseline 不要模型。**R1 级别的推理能力就是在这套便宜组件上规模化出来的**——便宜才做得大，大才出涌现。

## 一条线看完

```text
RLHF（2022）  SFT + RM + PPO        四个模型，驯兽
DPO （2023）   拆掉 RM 和 RL          偏好直接变梯度
GRPO（2024-）  再拆掉 value network   同伴对比当锚点 + 可验证奖励
```

每代拆掉的不是"没用的部件"，而是**最贵、最不稳的那个**。这和推理那边的故事惊人同构：KV Cache 从 32 份到 1/40，对齐从四个模型到一个损失函数——**这个领域的进步史，一半是压缩史**。
