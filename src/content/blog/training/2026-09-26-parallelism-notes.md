先说结论：**五种并行回答的是同一个问题**——模型太大、太慢，一张卡装不下、算不动。差别只在**刀落在哪、换来什么通信**：

| | 并行 | 切的对象 | 一句话 | 通信形态 | 用在哪 |
|---|---|---|---|---|---|
| ① | DP 数据并行 | batch | 模型复印 N 份，各算各的样本 | all-reduce（梯度） | 最普适，首选 |
| ② | TP 张量并行 | 权重矩阵 | 矩阵按列撕开，各算各的切片 | all-gather / all-reduce（每层） | 节点内 NVLink |
| ③ | PP 流水线并行 | 层 | 模型切几段，microbatch 流水过 | 点对点（激活） | 跨节点 |
| ④ | SP 序列并行 | 序列 | 沿序列维切开 | all-gather/reduce-scatter 或 all-to-all | 省激活 / 长序列 |
| ⑤ | EP 专家并行 | 专家 | token 按路由流动到专家卡 | all-to-all（token） | MoE 专属 |

记法：**切数据、切参数、切时间、切序列、切专家**。下面逐一讲含义、思路、流程和通信账。

## ① DP：切 batch——模型不动，样本分工

**含义**：每张卡放一份**完整模型**，batch 切成 N 份，各算各的。

**思路**：「模型放得下，只是算得慢」。样本与样本之间在前向/反向里互不相干（Loss 是各样本求和），所以把工作量分掉最自然——这是扩展性最好、最普适的一种，也是所有并行方案的底子。

**流程**：

1. batch 切 N 份，每卡一份；
2. 各卡独立前向 + 反向，得到**各自的**梯度；
3. all-reduce 把所有卡的梯度求和平均；
4. 每卡拿到**同一个**平均梯度，各自更新参数。

因为梯度一致、初始参数一致，N 份模型始终保持一模一样——训练结果严格等价于一张卡跑大 batch。

**白话**：全班复印同一本教材，各做各的卷子，考完把错题订正汇总，大家改同一版。

**通信账**：每步 all-reduce，量 $\approx 2\Phi$（$\Phi$ = 参数量，梯度进出各一次）。通信量随卡数线性增长，卡多了收益下降；global batch 太大还得降学习率。进化路线是 **ZeRO** 三刀——ZeRO-1 切优化器状态、ZeRO-2 切梯度、ZeRO-3 连参数也切（FSDP 就是 ZeRO-3 的实现）：ZeRO-1/2 用 reduce-scatter 替代 all-reduce，通信降到 $\approx \Phi$；ZeRO-3 再加两次参数 all-gather，回到 $\approx 3\Phi$，换每卡显存 $\div N$。这三刀切的对象正好是[显存账本](/blog/2026-09-26-training-memory-notes/)里参数/梯度/优化器状态三块大头。

## ② TP：切权重——矩阵按列撕开，各算各的切片

**含义**：把**单个权重矩阵**切开分到多卡，每卡算矩阵的一部分。

**思路**：矩阵乘天然可分块。$A$ 按列切、$B$ 按行切，各算各的，中间结果相乘后汇总——数学上严丝合缝，不需要近似。

**流程**（Megatron 风格，MLP 两块为例）：

1. 输入 $X$ 复制到每张卡（或已按列分片）；
2. 第一层**列并行**：$A$ 按列切成 $A_i$，各卡算 $A_i X$，输出按列分片（`f` 通信点）；
3. 第二层**行并行**：$B$ 按行切成 $B_i$，各卡算 $B_i (A_i X)$ 得到部分和；
4. all-reduce 把部分和加起来（`g` 通信点）——**每层两次通信**。

attention 的切法同理：QKV 按 head 切，各卡算自己那份 head 的 attention，输出投影后 all-reduce 汇总。

**白话**：一堵墙四个人砌，每人一条竖条，砌完拼起来——墙是完整的，但拼缝（通信）每层都有。

**通信账**：通信每层发生、量等于激活大小，频率是所有并行里最高的，对带宽极敏感 → **只在节点内 NVLink 用**（通常 ≤8 卡）。跨节点网速比 NVLink 慢一个量级，通信会反客为主，这就是「TP 不出节点」的原因。

## ③ PP：切层——模型切几段，microbatch 流水过

**含义**：模型按**层**切成 $p$ 段，每卡一段；数据切成 $M$ 个 microbatch，像流水线一样流过。

**思路**：「层与层是串行依赖，但不同数据之间是并行的」——用数据的并行去填层的串行，所以它切的其实是**时间**。

**流程**：

1. batch 切 $M$ 个 microbatch；
2. mb1 在 GPU0 算完前向交给 GPU1，GPU0 立刻算 mb2……前向波依次往后传；
3. 反向波倒着传回来；
4. GPipe：攒齐全部梯度，统一更新一次参数。

**白话**：汽车流水线，每道工序一台机器。刚开工时后面的机器在等料，快收工时前面的机器在等料——等的这段就叫 **bubble**（泡泡）。

**通信账**：GPipe 的 bubble 比例 $\approx \dfrac{p-1}{p-1+M}$：microbatch 越多 bubble 越小，但途中要暂存的激活也越多（显存换时间）。**1F1B** 改进：流水线填满后每卡前向/反向交替做，bubble 压到约 $\dfrac{p-1}{M}$，接近减半。通信只有层间激活、点对点、量小 → **适合跨节点**。各段负载不均（首尾层 vs 中间）也是常被吐槽的点。

## ④ SP：切序列——一位是省激活，一位是长序列

「序列并行」有两位，面试常混，分开说。

**SP-A（Megatron 的 sequence parallelism）：配合 TP 省激活。** TP 里每张卡都存整份输入 $X$（序列 × hidden），激活显存浪费。观察：LayerNorm、Dropout 沿序列维本来就是**逐 token 独立**的，可以放心切——各卡只算自己那 $1/p$ 段；进 attention 前 all-gather 拼回、出来再 reduce-scatter 切回。效果：激活显存 $\div p$，代价只是 LN 附近两次通信。

**SP-B（长序列的 context/sequence parallel）：attention 矩阵是 $N\times N$，序列太长单卡放不下。** 把序列切 chunk 分给多卡，但 attention 要「看全行」——两种解法：**Ring Attention**（KV 块沿环传一圈，每卡轮流看过所有 KV）或 **Ulysses**（按 head 切，QKV 各按 head 分片，all-to-all 交换）。FlashAttention 的分块恰好让「传阅 KV 块」成为可能，两者是天然搭档（见 [FlashAttention 那篇](/blog/2026-09-26-flashattention-notes/)）。

**白话**：一长条纸裁几段分人读，但答题要看整行——要么大家传阅（ring），要么按题号分工互相抄（Ulysses）。

**通信账**：SP-A 只省激活、不省权重，且必须和 TP 一起用才有意义；SP-B 通信量与序列长度成正比，序列不够长时不如直接上 TP。

## ⑤ EP：切专家——货不动，token 动

**含义**：MoE 的专家分散在不同卡，token 按路由结果送到对应专家所在的卡。

**思路**：专家太多单卡装不下，而且每步只有 top-k 个专家被激活——「货（专家）不动，人（token）动」。

**流程**：

1. 各卡算出自己 token 的路由结果（token → 专家映射）；
2. all-to-all **dispatch**：按目标专家把 token 发到对应卡；
3. 各卡算自己专家的 FFN；
4. all-to-all **combine**：结果送回原卡；
5. 继续后面的层。

**白话**：医院分诊台，按病症把病人送到对应科室，看完送回大厅继续排队。

**通信账**：两次 all-to-all，量 = token × hidden × 2，且 top-k 路由下专家负载天然不均，忙的卡没算完、闲的卡干等。DeepSeek 的解法：**细粒度专家**（更多、更小的专家）+ **共享专家**（人人路过都算）+ **辅助 loss**（平衡负载）。all-to-all 对网络拓扑敏感，所以 EP 的卡通常部署在同一节点/机架内。

## 组合与选型

- **3D 并行 = DP × TP × PP**（Megatron-LM 标准）：DP 管横（跨机扩展）、TP 管单节点内、PP 管纵（跨节点流水），三者在**正交维度**上相乘（世界规模 = d × t × p）。
- **DeepSeek-V3** 是混合范本：EP + DP + SP + DualPipe 的 PP，TP 几乎不用——EP 已经解决了 MoE 的显存问题，TP 每层高频通信不值得。
- **选型口诀**：先 DP（ZeRO 扛），单卡放不下模型再上 TP（节点内）/ PP（跨节点），序列超长加 SP/CP，MoE 必上 EP。

## 总结

- **DP 切 batch**：通信 all-reduce（梯度，≈2Φ）；ZeRO/FSDP 把状态也切了，通信换显存；
- **TP 切矩阵**：通信每层 all-gather/all-reduce，频率最高 → 限节点内；
- **PP 切层**：通信点对点（激活，量小）→ 可跨节点；代价是 bubble，1F1B 压半；
- **SP 切序列**：Megatron 版省激活（配 TP），长序列版（ring/Ulysses）撑超长上下文；
- **EP 切专家**：两次 all-to-all 搬 token；负载均衡是工程核心；
- **组合**：五种并行全部正交，实际系统按「DP 打底 → TP/PP 撑模型 → SP/EP 补短板」层层叠加。

## 延伸

- **ZeRO/FSDP2**：DP 的分片路线，FSDP2 用每参数分片（DTensor）实现，与 TP 可以共存；
- **DualPipe**（DeepSeek-V3）：把前向、反向、通信三条流水线叠起来，bubble 压到近零，计算与通信互相藏延迟；
- **USP**：把 Ulysses、Ring、Megatron SP 统一起来的混合序列并行框架，按序列长度自适应切换；
- **与本站联动**：[显存账本](/blog/2026-09-26-training-memory-notes/)讲单卡显存的三块大头（ZeRO 三刀的对象）；[FlashAttention](/blog/2026-09-26-flashattention-notes/)的分块让 KV 传阅（ring attention）成为可能。
