[KV Cache 笔记](/blog/2026-08-15-kv-cache-notes/)里手算过：70B 级模型 2.6 MB/token，长上下文下缓存比权重还大。当时留的坑——"MLA/GQA 这些减少 KV 头的压缩路线"——就是这篇。三步演进，一次比一次狠。

## 起点：MHA 的浪费

标准多头注意力（[Attention 笔记](/blog/2026-08-15-attention-from-scratch/)里的版本）有 h 个头，每头独立的 K 和 V。KV Cache 的账：**每层每 token 存 h 份 K、h 份 V**。40 层 × 32 头，一个 token 的缓存就是几十组向量。

问题是：这 32 组 K、V 里有大量冗余——不同的头看的世界差不多，只是视角不同。

## 第一步 MQA：所有人共用一份 KV

最粗暴的压缩：所有 Query 头共享**同一组** K、V。KV Cache 直接除以头数（32 头 → 1/32），效果立竿见影。

代价：质量掉。Q 有 32 个视角，K/V 只有 1 个视角，注意力能表达的模式变少。推理快了不少，但生成质量肉眼可见地糙——"1 份共享"压得太狠了。

## 第二步 GQA：分组共享（折中的艺术）

Llama 系采用的方案：不共享 1 份，也不各用各的——**分成 8 组，每组 4 个 Q 头共用一份 KV**。

KV Cache 降到 1/4，质量几乎追平 MHA（经验上 8 组就够）。这是典型的工程答案：不做极端选择，找**压缩率和质量的拐点**。我的记忆钩子：MQA 是大锅饭，MHA 是单人小灶，GQA 是 4 人拼桌。

## 第三步 MLA：不存 K/V，存"原料"（DeepSeek 的路线）

真正的换思路。前面两步都在"少存几份成品"，MLA 问的是：**为什么要存成品？**

MLA（Multi-head Latent Attention）的做法：

1. 每个 token 先压成一个低维隐向量 c（比如几百维，远小于 h × head_dim）；
2. KV Cache **只存 c**；
3. 需要算注意力时，K 和 V 再从 c **现场投影还原**出来。

妙处在两处。其一，压缩率远超 GQA——DeepSeek-V3 的 KV Cache 压到 MHA 的约 1/40，同样是长上下文，账单直接换个量级。其二，"还原"这一步可以**吸收进权重矩阵**（矩阵乘结合律，先投影再还原的两步合成一步），推理时几乎不多花计算——**存的是压缩包，用的时候解压是免费的**。

代价：训练和实现复杂度高、灵活性差（比如和某些 attention 变体的兼容），所以 GQA 仍是多数模型的稳妥选择，MLA 是敢把 KV 账算到极致的路线。

## 三步摆在一起看

```text
MHA    每头各存一份 KV          ×1    （基线）
MQA    全体共用一份             ×1/32 （质量崩）
GQA    分组共用（8 组）         ×1/8~1/4（质量≈满血，主流）
MLA    存低维隐向量，用时还原   ×1/40 （极致，DeepSeek 路线）
```

演化方向出奇地一致：**KV Cache 是最贵的资产，一切设计围着它转**。PagedAttention 优化它住哪（[KV Cache 篇](/blog/2026-08-15-kv-cache-notes/)），PD 分离优化它怎么搬家（[PD 分离篇](/blog/2026-08-15-pd-disaggregation-notes/)），GQA/MLA 优化它**要不要存在**。三条线正在合流——最新一代模型的卖点几乎都是"长上下文 + 便宜推理"，背后全是这套账。
